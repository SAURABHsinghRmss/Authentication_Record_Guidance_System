# Administrator Role (admin.txt) — Minute Functional Specifications

> Detailed technical breakdown of every function, route, database mechanism, and UI component associated with the **Administrator** (`admin`) role in EduIdentityAI.

---

## 1. System-Wide Student Database Administration (CRUD) (Implemented)
* **Function Purpose**: Full relational lifecycle management for student academic records stored in the 3NF SQLite/PostgreSQL database.
* **API Endpoints**:
  * `GET /api/students`: Fetches all student records with pagination and filtering.
  * `POST /api/students`: Registers a new student record (requires `roll_no`, `name`, `email`, `department`, `semester`, `cgpa`, `attendance_percentage`, `credits_earned`, `backlogs`).
  * `DELETE /api/students/{id}`: Purges a student record by UUID.
* **Frontend UI**: Admin CRUD dashboard table with instant add/delete modals and 3NF input guidance tooltips.

## 2. Polyglot 7-Database Domain Federation Management (Implemented)
* **Function Purpose**: Complete oversight and orchestration of the 7 isolated domain database architecture:
  * Domain 1: `databases/auth_iam.db` (User identities, credentials, role permissions)
  * Domain 2: `databases/academic_sis.db` (Student records, transcripts, courses, enrollments)
  * Domain 3: `databases/family_heritage.db` (Parent-ward linkages, socio-economic background)
  * Domain 4: `databases/institutions_governance.db` (College registrations, AICTE/UGC accreditation)
  * Domain 5: `databases/security_audit.db` (Immutable event log streams, tamper-detection hashes)
  * Domain 6: `databases/career_pathways.db` (Technical skill roadmaps, placement drives)
  * Domain 7: `databases/notifications_events.db` (Real-time alerts, notice broadcasts)
* **API Endpoints**:
  * `GET /api/admin/db/federation-health`: Evaluates live connectivity across all 7 databases.
  * `GET /api/admin/db/audit-trail`: Fetches system-wide security audit trails.
  * `POST /api/admin/db/sync-all`: Triggers cross-database consistency synchronization.
* **Frontend UI**: Database Federation Health & Cross-Domain Audit widgets in the Admin console.

## 3. Institution Verification & Approval Workflow (Implemented)
* **Function Purpose**: Reviewing and approving unverified schools and colleges submitted by users during registration.
* **API Endpoints**:
  * `GET /api/auth/institutions/pending`: Lists all unverified institutional requests.
  * `POST /api/auth/institutions/{id}/approve`: Marks an institution as verified (`institution_verified = true`).
* **Frontend UI**: Institution Requests approval tab in Admin portal with one-click verification dispatch.

## 4. Unified 3-Category Chat & Agora Governance (Implemented)
* **Function Purpose**: System-wide communication oversight and official broadcast broadcasting:
  * Broadcasting critical institutional notices to `#campus_global` Agora.
  * Monitoring community clubs and private group activity counters.
  * Managing EduMentor Meta AI integration across all 8 educational criteria.
* **API Endpoints**:
  * `GET /api/chat/categories`
  * `POST /api/chat/send`
  * `GET /api/chat/ai/criteria`
* **Frontend UI**: Integrated Unified Campus Agora & Chat Room (`unified_chat` tab).

## 5. Storage Location Auditing & Cloud Synchronization (Implemented)
* **Function Purpose**: Inspecting partitioned per-user Gmail storage directories and staging logs for cloud backup.
* **API Endpoints**:
  * `GET /api/auth/work-logs/locations`: Returns filesystem inventory of `storage/logs/users/`.
  * `GET /api/auth/work-logs/user/{email}`: Returns activity streams and login history for a specific user.
  * `POST /api/auth/work-logs/cloud-sync`: Triggers Gzip compression and multi-cloud bucket synchronization (`gs://eduidentity-user-logs/...`).
* **Frontend UI & Telemetry**: Integrated audit log inspection and cloud sync status widgets.

## 6. Master Developer Account Immunity (`msrch`) (Implemented)
* **Function Purpose**: Providing a permanent, tamper-proof master developer account for system debugging and emergency intervention.
* **Database Mechanism**: PostgreSQL / SQLite database trigger `prevent_delete_msrch` intercepts any `DELETE` operation on the `users` table where `username = 'msrch'`, immediately raising a fatal database exception (`RAISE EXCEPTION`).
* **SQLAlchemy ORM Defense**: Lifecycle event listener `@event.listens_for(UserModel, 'before_delete')` rejects programmatic deletion attempts with HTTP 403 Forbidden.
